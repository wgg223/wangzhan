# 账户功能使用手册

本手册覆盖三块账户相关功能：**用户批量导入**、**权限二级审批流**、**后台用户/权限管理界面**。

适用角色：
- 超级管理员（超管）：全部功能
- 管理员（admin）：审批、查看
- 普通用户（user）：权限申请、查看自己的申请进度

---

## 一、用户批量导入（仅超级管理员）

### 1.1 入口

后台 → 「👥 用户管理」→ 右上角「📥 批量导入」按钮。

### 1.2 文件格式要求

支持 **CSV**（UTF-8 / GBK 编码自动识别）与 **Excel**（xlsx / xls）文件。

- 单文件 ≤ **10MB**，单次最多 **1000 行**（超出请分批导入）
- 第一行为表头，支持中英文列名，五个字段如下：

| 列名（英文） | 列名（中文别名） | 必填 | 说明 |
|---|---|---|---|
| `username` | 用户名 / 账号 | 是 | 至少 3 个字符，不可与现有用户重复 |
| `password` | 密码 | 是 | 至少 8 位 |
| `email` | 邮箱 / 电子邮件 | 否 | 不可与现有邮箱重复 |
| `role` | 角色 | 否 | `user`（用户，默认）/ `admin`（管理员）/ `visitor`（访客），支持写中文「用户/管理员/访客」 |
| `superior` | 上级管理员 / 对应管理员 / 上级 | 否 | 填该用户对应上级管理员的**用户名**，可填同文件内创建的用户 |

### 1.3 操作步骤

1. 点击「📥 批量导入」打开弹窗；
2. （推荐）先在弹窗内下载 **CSV 模板** 或 **Excel 模板**，按模板填写；
3. 点击「选择文件」上传填写好的文件；
4. 点击「开始导入」，等待处理完成；
5. 查看导入结果面板：显示**成功数、失败数**及每条失败记录的行号与原因（如「第 5 行『zhangsan』：用户名已存在」）；
6. 点击「刷新列表与导入历史」查看新用户。

### 1.4 规则说明

- **逐行容错**：单行失败不影响其他行导入；失败原因精确到行号。
- **两段式写入**：先创建全部用户，再统一设置 `superior` 上级关系。因此**同文件内用户可以互相指定为上级**（如 A 行的 superior 填 B 行的用户名）。若上级用户名不存在或校验失败（自指 / 循环链 / 角色不符），该行计入失败。
- **角色权限**：导入的管理员（admin）自动获得全部权限点；其他角色获得系统默认权限。
- **导入历史**：页面底部「批量导入与历史」表格记录每次导入的时间、文件名、总数、成功/失败数、操作人，失败明细可展开逐条查看（最多保留 200 条明细）。

### 1.5 常见失败原因

| 提示 | 处理方式 |
|---|---|
| 用户名无效（至少3个字符） | 补长用户名 |
| 密码无效（至少8位） | 补长密码 |
| 用户名已存在 / 邮箱已被使用 | 换名或换邮箱；重复行可跳过 |
| 上级管理员 "xxx" 不存在 | 检查 superior 列用户名拼写 |
| 设置该上级会形成循环审批链 | A→B 且 B→A 之类的关系不允许 |
| 上级必须是管理员或超级管理员角色 | superior 只能填 admin / super_admin 用户 |
| 单次导入最多 1000 行 | 拆分文件分批导入 |

## 二、权限二级审批流

### 2.1 流程总览

所有权限变更都通过用户的「权限申请」发起（后台不做直接授予），审批分两条路径：

```
基础权限：用户申请 ──> 对应管理员一级审批 ──> 系统自动确认生效
                        （未指定对应管理员时由超级管理员兜底审批）

高危权限：用户申请 ──> 对应管理员一级审批 ──> 管理员的上级二级终审 ──> 生效
（用户/权限/设置/数据管理类权限，以及管理员申请任意 .manage 权限，
  均自动判定为高危流程）
```

- **对应管理员**：由超级管理员在「用户管理」中为每个用户指定的上级管理员（`superior` 关系）。
- **兜底规则**：用户未指定对应管理员（或审批人自身没有上级）时，由超级管理员代为审批；**已指定审批人后，超级管理员不可越级审批**，保证二级审批语义。
- 任意阶段被拒绝，流程立即终止并通知申请人（含拒绝原因）。

### 2.2 各角色操作

#### 普通用户（申请方）

1. 进入「🔑 权限申请」页（登录后侧边栏 / 后台入口均可）；
2. 页面顶部显示您的**对应管理员**姓名（未指定时提示由超管审批）；
3. 点击权限卡片的「申请」按钮，填写理由（≤500 字）提交；
4. 在页面底部「申请记录」中跟踪状态：
   - ⏳ 待审核 —— 一级审批中（对应管理员）／ 二级审批中（上级终审）
   - ✅ 已通过（高危权限会显示「高危」标识）
   - ❌ 已拒绝（附拒绝原因）
5. 每小时最多提交 5 条申请；待审核期间可「取消」申请。
6. 审批通过/拒绝会收到站内通知。

#### 管理员（审批方）

1. 进入后台「📝 我的审批」（侧边栏「用户与权限」组），列表只显示**等待您审批**的申请；
2. 每条申请显示申请人、权限、类型（基础/高危）、当前阶段、理由与时间；
3. 点击「✓ 批准」或「✗ 拒绝」（拒绝可填原因，展示给申请人）；
4. **高危申请您批准后不会立即生效**，系统自动转交您的上级终审并通知对方；
5. 基础申请您批准后系统立即自动确认生效并通知申请人。

#### 超级管理员

- 除与普通管理员相同的审批操作外，还负责：
  - **指定对应上级管理员**：「用户管理」→ 目标用户行「上级管理员」列 ⚙️ 按钮 → 下拉选择 → 保存（选「未指定」= 清除，审批由超管兜底）；
  - 兜底审批未指定对应管理员的申请（在「我的审批」与「权限管理」中均可处理）；
  - 在「权限管理」页查看全部申请的完整审批链（一级审批人 → 二级审批人 → 系统确认时间）。

### 2.3 审批状态说明

| 状态 | 含义 |
|---|---|
| 🟢 基础 / 🔴 高危 | 流程类型。高危 = 用户/权限/设置/数据管理类，或管理员申请 .manage 权限 |
| 一级 · 对应管理员审批 | 等待申请人的对应管理员处理 |
| 二级 · 上级终审 | 高危权限一级已通过，等待一级审批人的上级处理 |
| ✅ 已批准 | 权限已生效（历史记录中可见系统确认时间） |
| ❌ 已拒绝 | 任意阶段被驳回，附原因 |

### 2.4 通知机制

- 用户提交申请 → 对应审批人收到站内通知「有新的权限申请待您审批」；
- 高危一级通过 → 二级审批人收到站内通知；
- 审批完成 → 申请人收到通过/拒绝通知（含拒绝原因）。

## 三、后台管理界面说明

### 3.1 用户管理页（/admin/users）

- **筛选栏**：按关键词（用户名/邮箱模糊匹配）、角色、状态组合筛选，支持分页（每页 50 条，筛选条件跨页保留）；
- **用户列表**：
  - 用户名旁「🔐 权限」链接 → 跳转权限管理页并**自动高亮定位**该用户（联动查询）；
  - 「上级管理员」列显示该用户的对应管理员（超管可点击 ⚙️ 设置/清除）；
  - 角色下拉即时切换（仅超管）、状态操作（通过/禁用/启用/重置密码/删除）与旧版一致；
- **批量导入区**（仅超管）：导入入口按钮、模板下载、导入历史表；
- 非超管进入为只读模式（仅可查看与跳转权限页）。

### 3.2 权限管理页（/admin/permissions）

- **待审核申请表**：新增「类型」「当前阶段」列；只有当前阶段的合法审批人能看到批准/拒绝按钮，其余人显示无权原因（如「该申请需由申请人的对应管理员审批」）；
- **申请历史表**：显示完整审批链（一级审批人 → 高危二级审批人 → 系统确认生效 / 驳回人），申请人可点击 👤 跳转用户管理页查询（联动）；
- **用户权限矩阵**：用户名旁 👤 链接跳转用户管理；从用户管理跳入时目标行高亮滚动定位；
- 撤销权限、权限点列表等其他功能与旧版一致。

### 3.3 我的审批页（/admin/my-approvals）

- 侧边栏「用户与权限」组新增入口（仅 admin / super_admin 可见）；
- 只列出当前登录用户作为指定审批人（或兜底超管）的待办申请，处理完毕自动从列表消失。

### 3.4 界面一致性

- 全部新页面沿用后台既有设计体系（section-card 卡片、badge 徽标、表格与弹窗规范、暗色变量）；
- 侧边栏当前页高亮修复（此前高亮不生效），交互与既有页面保持一致。

## 四、安全与审计

- 批量导入、指定上级、审批、授予/撤销权限全部写入**操作日志**（action：import / update / approve / reject / grant / revoke 等），后台「操作日志」可追溯；
- 批量导入仅超管可用，接口双重校验（文件类型白名单 + 10MB 限制 + 1000 行上限）；
- 审批接口按审批链逐条校验操作人身份，未到阶段/无权审批一律 403；
- 指定上级时校验：上级必须存在、必须为管理员/超管、不可自指、不可形成循环链；
- 后台全部写操作受 CSRF 双提交 Cookie 防护。
