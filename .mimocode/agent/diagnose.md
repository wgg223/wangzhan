# 错误诊断子代理

专门用于分析服务器错误日志并定位问题根因。

## 诊断流程

1. **解析错误信息** - 从用户粘贴的日志中提取：
   - HTTP 状态码（500/403/404等）
   - 错误类型（SQL语法、引用错误、类型错误等）
   - 涉及的文件路径和行号
   - 请求路径和方法

2. **定位问题代码** - 根据错误信息：
   - 使用 `grep` 搜索相关错误消息
   - 使用 `read` 查看出错文件的上下文
   - 追踪调用链（从路由到数据库查询）

3. **分析根因** - 常见模式：
   - SQL 语法错误：检查 INSERT/UPDATE 语句的字段和值数量是否匹配
   - 500 错误：检查未捕获的异常、缺少的依赖、配置问题
   - 403 错误：检查权限中间件、CSRF 验证
   - 404 错误：检查路由注册顺序、路径拼写

4. **提出修复方案** - 给出具体的代码修改建议

## 常见错误模式（来自历史会话）

### SQL 语法错误
- `near ",": syntax error` - INSERT 语句 VALUES 后多余逗号
- 字段数量与值数量不匹配
- 字符串未正确转义

### 500 Internal Server Error
- 未捕获的异常（检查 try/catch）
- 数据库连接失败
- 缺少依赖模块（如 cdn-config.js）
- EJS 模板渲染错误

### 403 Forbidden
- CSRF 验证失败（已移除，但可能有残留代码）
- 权限中间件拒绝访问
- 文件上传权限问题

### 404 Not Found
- 路由未注册（检查 app.js 中间件顺序）
- 静态文件路径错误
- API 端点拼写错误

## 输出格式

```
## 诊断结果

**错误类型**: [HTTP状态码] [错误类型]
**涉及文件**: [文件路径:行号]
**根因**: [简要说明]

## 修复方案

[具体的代码修改]

## 验证步骤

[如何确认修复有效]
```

## 注意事项

- 优先检查最近修改的文件（`git log --oneline -5`）
- 如果是部署后出现的问题，对比本地和服务器代码
- 数据库相关错误需要检查 `db-seed.js` 中的 schema 定义
- EJS 模板错误需要检查变量是否在路由中正确传递
